# 스마트스토어 상품별 내보내기 가격 조정

판매처 내보내기의 스마트스토어 카드에서 기존 가격 모드와 범위를 선택해 미리보기한 뒤 `상품별 가격 조정`을 연다. 판매처 상품코드별 목록·상태 필터·검색, 공통 등록 판매가·기본 즉시할인 입력, 고정 목표 최종가와 자동 계산 옵션가를 한 창에 표시한다. 옵션 표는 전체 옵션을 스크롤하며 확인한다.

입력과 `추천값 채우기`는 미적용 수정안만 바꾼다. `적용 후 다시 미리보기`가 최신 원본·가격으로 재검증에 성공해야 수정안과 미리보기 계약을 확정한다. 실패·취소·뒤늦은 응답은 적용된 수정안을 덮지 않는다. 기존 XLSX 생성은 확정된 수정안과 같은 미리보기 계약을 사용한다. 범위·가격 모드·원본·목표 가격이 바뀌면 수정안을 다시 확인해야 한다.

## 가격 계약

- 수정할 수 있는 값은 상품 공통 등록가와 원 단위 기본 즉시할인이다. 기본할인이 없는 원본에 새 기본할인을 추가하거나, 명시적으로 기존 기본할인을 원 단위로 바꿀 수 있다. 0원 입력은 기본할인을 제거한다.
- 수식·셀피아 원본·종속관계로 선택한 옵션 최종가를 고정한다. 미선택·미매핑 형제는 판매처 원본 최종가를 유지한다. 할인 후 기준가와 옵션가는 읽기 전용이다.
- `할인 후 기준가 = 공통 등록가 − 기본 즉시할인`, `옵션가 = 목표 최종가 − 할인 후 기준가`로 계산한다. 파일이 지원하는 원본 할인 표현만 사용하며 모바일·예약·복수구매 등 다른 할인 메타데이터는 보존한다.
- 기존 내보내기의 보수적인 옵션가 범위를 유지한다. 새 수동 조정은 0원 옵션 존재와 판매가 2,000원 미만의 음수 옵션 금지도 검사한다. 추천 기준가는 실제 목표 최종가 중에서 선택해 0원 옵션을 만들고, 모든 옵션이 범위 안에 들도록 등록가와 기본할인을 구성한다.
- 시안의 9,000원/2,000원은 설명용이다. 이 구성이 유효하려면 목표 최종가 7,000원인 옵션이 존재해야 한다. 없다면 다른 입력이나 추천값을 사용한다. [스마트스토어 공식 옵션 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3358)
- 현재 확정 가격 결정을 유지하는 옵션이 있으면 그 상품은 조정을 잠근다. 명시적으로 상위 최종가를 상속하는 하위 옵션에는 이미 승인된 종속 내보내기 계약을 적용한다. 다른 옵션의 확정 결정을 묵시적으로 변경하지 않는다.
- 모호한 연결, 중복 상품·옵션 identity, 누락된 목표가, 해석할 수 없는 원본 가격·할인, 읽기 전용 할인, 누락된 재고 target은 이 기능으로 해제할 수 없다.

## 생성과 검증

`product-price-adjustment.js`는 원본을 복사하여 계산하는 순수 모듈이다. `current-price-export.js`는 가격 기준별 고정 목표가를 추출하고, 조정한 가격 지시만 기존 계획에 합친다. 독립 재고 작업은 유지한다.

동일 상품이 스마트스토어 원본 두 파일에 나뉘어 있어도 모든 형제 옵션을 먼저 합쳐 검증한다. 선택 SKU가 한 파일에만 있어도 다른 파일의 같은 상품을 포함하며, 상품 전체에서 0원 옵션·공통 가격·고정 최종가를 검증한 다음 각 파일의 해당 행을 생성한다. 파일 간 같은 옵션 identity가 중복되면 잠근다.

정규화된 수정안과 전체 가격 증거를 미리보기 fingerprint에 포함한다. XLSX 생성 뒤 실제 Blob을 다시 파싱하여 전체 옵션 개수·identity·등록가·할인·옵션가·최종가를 확인한다. 생성 직전에 현재 가격 결정, 원본 가격 또는 수식 결과, 종속관계와 원본 파일 바이트도 다시 확인한다. 변경되면 다운로드하지 않는다.

수정안은 브라우저 메모리의 이번 내보내기 설정이며 DB·수식태그·종속관계·연결·원본 파일을 저장하거나 갱신하지 않는다. 스마트스토어 가격 내보내기만 확장하며, 재고 전용·메이크샵·에이블리의 기존 흐름은 유지한다.

## 회귀 검증과 롤백

순수 계산·입력 경계·변경 증거 테스트, 실제 app·데이터 서비스·파서·XLSX 변환기 통합 테스트, 모달 및 적용 트랜잭션 브라우저 테스트를 실행한다. 미선택·미매핑 형제, 한 물리 행의 수백 옵션, 상품의 파일 간 분할, 전체 원본·대상 전체·변경분·가격 전용, 기존 재고·코드·비가격 셀·스타일·OOXML 구성 보존을 확인한다. 출력 Blob 손상 및 생성 중 가격·원본·관계 변경도 차단한다.

DB 마이그레이션은 없다. 프런트엔드를 이전 운영 commit `58f862a3e2efeaf44268a7e26d3d8e298e851045`로 복원하면 이 기능 추가 전 동작으로 돌아간다.
