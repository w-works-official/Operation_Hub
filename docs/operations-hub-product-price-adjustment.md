# 스마트스토어 상품별 내보내기 가격 조정

판매처 내보내기의 스마트스토어 카드에서 기존 가격 모드와 범위를 선택해 미리보기한 뒤 `상품별 가격 조정`을 연다. 판매처 상품코드별 목록·상태 필터·검색, 공통 등록 판매가·기본 즉시할인 입력, 고정 목표 최종가와 자동 계산 옵션가를 한 창에 표시한다. 옵션 표는 전체 옵션을 스크롤하며 확인한다.

입력과 `추천값 채우기`는 미저장 수정안만 바꾼다. `저장 후 다시 미리보기`는 최신 원본·목표 가격으로 검증한 뒤 변경한 상품의 판매가·기본할인만 함께 저장하고, 저장된 버전으로 다시 미리보기한다. 저장 요청을 보내기 전에는 취소할 수 있고, 요청 중에는 닫기·취소를 잠가 저장 결과를 확인한다. 저장이 완료된 뒤 미리보기가 실패하면 저장 완료와 미리보기 재실행 필요를 구분하고 다운로드를 막는다.

상품 목록에 초점이 있을 때 `Tab`은 현재 검색·상태 필터에 보이는 다음 상품, `Shift+Tab`은 이전 상품을 선택한다. 목록의 처음·끝에서는 기본 초점 이동으로 목록을 벗어난다. `Enter`는 선택한 상품의 판매가 입력으로 들어간다. 검색·가격·할인·후보 선택·저장 버튼에서는 기본 Tab 이동을 유지한다. 입력한 수정안은 상품을 옮겨도 유지하며 저장·최신 가격 검증 중에는 상품 이동을 막는다.

`전체 추천값 채우기`는 현재 내보내기 미리보기의 모든 상품을 대상으로 한다. 검색·상태 필터로 가려진 상품도 포함한다. 조정 가능한 상품만 새로 추천·검증하여 판매가와 기본할인을 채우며, 조정 불가·추천 불가 상품의 기존 수정안은 유지한다. 저장값과 같은 추천은 불필요하게 다시 저장하지 않고, 저장값이 없는 상품은 원본과 같더라도 명시적으로 저장할 수 있다. 이 버튼은 DB를 호출하지 않으며, `저장 후 다시 미리보기`를 눌러야 확정된다. 저장은 기존의 단일 트랜잭션 최대 500상품 계약을 유지하며 초과 시 저장을 막고 미리보기 대상 축소를 안내한다. 목표 최종가·수식·종속관계는 바꾸지 않는다.

일반 미리보기는 매번 판매처 상품코드별 저장값을 DB에서 읽는다. 새로고침·로그아웃·다른 PC에서도 저장값을 다시 사용할 수 있다. 범위·가격 모드·원본·목표 가격이 달라져도 저장값 자체를 삭제하지 않으며, 최신 수식·종속관계의 목표 최종가로 옵션가를 다시 계산한다. 저장값이 새 목표 가격에 맞지 않으면 해당 상품을 조정 필요로 표시하고 원본 가격으로 묵시적으로 대체하지 않는다.

## 가격 계약

- 수정할 수 있는 값은 상품 공통 등록가와 원 단위 기본 즉시할인이다. 기본할인이 없는 원본에 새 기본할인을 추가하거나, 명시적으로 기존 기본할인을 원 단위로 바꿀 수 있다. 0원 입력은 기본할인을 제거한다.
- 수식·셀피아 원본·종속관계로 선택한 옵션 최종가를 고정한다. 미선택·미매핑 형제는 판매처 원본 최종가를 유지한다. 할인 후 기준가와 옵션가는 읽기 전용이다.
- `할인 후 기준가 = 공통 등록가 − 기본 즉시할인`, `옵션가 = 목표 최종가 − 할인 후 기준가`로 계산한다. 파일이 지원하는 원본 할인 표현만 사용하며 모바일·예약·복수구매 등 다른 할인 메타데이터는 보존한다.
- 기존 내보내기의 보수적인 옵션가 범위를 유지한다. 새 수동 조정은 0원 옵션 존재와 판매가 2,000원 미만의 음수 옵션 금지도 검사한다. 추천 기준가는 실제 목표 최종가 중에서 선택해 0원 옵션을 만들고, 모든 옵션이 범위 안에 들도록 등록가와 기본할인을 구성한다.
- 고정 기본할인 C에 대한 판매가 후보는 `B = C + 각 고정 최종가` 중 모든 옵션 검증을 통과하는 값이다. 최소·최대 사이의 모든 정수가 허용되는 연속 범위가 아니다. 화면은 후보 범위와 정확한 선택 금액 목록을 함께 보여주며 할인 변경 시 갱신한다. 오류 영역은 짧은 상태와 필요한 상세 접기만 사용한다.
- 시안의 9,000원/2,000원은 설명용이다. 이 구성이 유효하려면 목표 최종가 7,000원인 옵션이 존재해야 한다. 없다면 다른 입력이나 추천값을 사용한다. [스마트스토어 공식 옵션 안내](https://help.sell.smartstore.naver.com/faq/content.help?faqId=3358)
- 현재 확정 가격 결정을 유지하는 옵션이 있으면 그 상품은 조정을 잠근다. 명시적으로 상위 최종가를 상속하는 하위 옵션에는 이미 승인된 종속 내보내기 계약을 적용한다. 다른 옵션의 확정 결정을 묵시적으로 변경하지 않는다.
- 모호한 연결, 중복 상품·옵션 identity, 누락된 목표가, 해석할 수 없는 원본 가격·할인, 읽기 전용 할인, 누락된 재고 target은 이 기능으로 해제할 수 없다.

## 생성과 검증

`product-price-adjustment.js`는 원본을 복사하여 계산하는 순수 모듈이다. `current-price-export.js`는 가격 기준별 고정 목표가를 추출하고, 조정한 가격 지시만 기존 계획에 합친다. 독립 재고 작업은 유지한다.

동일 상품이 스마트스토어 원본 두 파일에 나뉘어 있어도 모든 형제 옵션을 먼저 합쳐 검증한다. 선택 SKU가 한 파일에만 있어도 다른 파일의 같은 상품을 포함하며, 상품 전체에서 0원 옵션·공통 가격·고정 최종가를 검증한 다음 각 파일의 해당 행을 생성한다. 파일 간 같은 옵션 identity가 중복되면 잠근다.

정규화된 수정안과 전체 가격 증거를 미리보기 fingerprint에 포함한다. XLSX 생성 뒤 실제 Blob을 다시 파싱하여 전체 옵션 개수·identity·등록가·할인·옵션가·최종가를 확인한다. 생성 직전에 현재 가격 결정, 원본 가격 또는 수식 결과, 종속관계와 원본 파일 바이트도 다시 확인한다. 변경되면 다운로드하지 않는다.

명시적 저장은 새 private 설정 테이블에 판매처·상품코드·공통 판매가·기본할인·revision과 작업자/시각만 보관한다. 고정 최종가·옵션가·수식태그·종속관계·연결·원본 파일과 기존 확정 가격 결정은 저장하거나 갱신하지 않는다. 스마트스토어 가격 내보내기만 확장하며, 재고 전용·메이크샵·에이블리의 기존 흐름은 유지한다.

새 `hub_product_price_settings_read_v1`/`save_v1` RPC는 기존 운영 세션 검증을 거쳐 private RLS 테이블에 접근한다. 조회는 기록을 생성하지 않는다. 여러 상품 저장은 전체 revision 비교 후 한 트랜잭션으로 처리하며, 요청 ID 영수증으로 분실 응답 재시도 시 중복 저장을 방지한다. 미저장 부재와 저장 revision을 미리보기 fingerprint에 포함하고 XLSX 다운로드 직전 다시 읽어 다른 작업자의 변경도 검출한다.

## 회귀 검증과 롤백

순수 계산·입력 경계·변경 증거 테스트, 실제 app·데이터 서비스·파서·XLSX 변환기 통합 테스트, 모달 및 적용 트랜잭션 브라우저 테스트를 실행한다. 미선택·미매핑 형제, 한 물리 행의 수백 옵션, 상품의 파일 간 분할, 전체 원본·대상 전체·변경분·가격 전용, 기존 재고·코드·비가격 셀·스타일·OOXML 구성 보존을 확인한다. 출력 Blob 손상 및 생성 중 가격·원본·관계 변경도 차단한다.

추가 마이그레이션은 `20261022044548_hub_product_price_settings_v1.sql`이다. 지속 저장을 추가하기 전 프런트엔드 checkpoint는 `caaf66cb95a7d6f12c2f55ff813a2dac7d87ec57`이다. 대응 rollback SQL은 새 RPC만 제거하고 운영자가 저장한 private 설정·요청 영수증 테이블을 보존한다. 프런트엔드를 먼저 checkpoint로 복원한 후 필요할 때 API rollback을 적용한다. 기존 가격·연결·원본에는 보상 쓰기가 필요하지 않다.
