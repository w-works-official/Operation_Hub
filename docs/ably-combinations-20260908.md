# 에이블리 조합관리로 방향 전환

## 2026-09-10: 전체 재고갱신과 1+1 등록용 파일

상단 왼쪽 전체 조합 재고갱신 파일은 불러온 옵션기본 파일의 모든 상품/조합을 대상으로 Q열 연결을 조회하고 원본 양식을 보존해 W열을 갱신한다. 조회 실패 시 파일을 생성하지 않으며, 확인 필요 행은 원본 재고를 유지하고 건수를 표시한다.

상단 오른쪽 상품 불러오기 · 조합등록 엑셀 생성은 개별 SKU 조회 및 체크박스 선택 화면을 연다. 선택한 N개를 옵션1과 옵션2에 각각 배치해 N×N개를 생성한다. 1000-1~1000-9는 81행이며 동일 SKU 9쌍과 순서가 바뀐 쌍을 포함한다. 사용자 승인 기준대로 동일 SKU끼리도 기존 최솟값 재고 기준을 유지하며 수량으로 나누지 않는다.

K/L열은 옵션1 명칭/값, M/N열은 옵션2 명칭/값, Q열은 두 정확한 SKU, W열은 재조회한 현재재고의 최솟값이다. 동일한 옵션명이 있는 SKU는 코드로 구분한다. 온라인 상품명/계정/판매자관리코드/판매가를 입력해야 다운로드할 수 있다. 임의의 운영 계정값을 자동 삽입하지 않는다.

검증: 관련 mock 테스트 82개 통과. 실제 재고를 사용하는 로컬 브라우저에서 생성 파일을 다운로드하고 35컬럼/81개 고유 옵션쌍/동일 SKU 9쌍을 확인했다. 같은 파일을 다시 불러와 전체 조합 재고갱신 다운로드를 실행했고 81행과 원본 값 보존을 확인했다. 테스트에는 QA_ONLY/QA_1000 식별값을 사용했다. 실제 상품등록이나 DB 재고 변경은 실행하지 않았다.

## 현재 기능: 개별 SKU 실재고 연결과 플랫폼 엑셀 출력

2026-09-08 추가 요청으로 가상 재고 입력 UI를 제거하고 기존 operations_hub_matrix_system_live의 system_stock(시스템 현재재고)를 읽도록 연결했다. 정확한 SKU로 100개씩 조회하며 재고값과 원본 갱신 시각을 표시한다. 이 변경에는 DB 쓰기나 새 권한 부여가 없다.

상품 하위 화면에서 Q열 연결을 수정하고 재고 새로고침/엑셀 다운로드를 할 수 있다. 다운로드 직전에 재고를 다시 읽는다. 조회 실패 시 다운로드하지 않으며, 연결 오류/재고 누락 행은 원본 W값을 유지하고 반영/유지 행 수를 표시한다. 계산 가능한 행이 하나도 없으면 다운로드를 중단한다.

업로드한 플랫폼 엑셀은 ZIP 내 옵션기본 시트의 변경한 Q셀과 계산 가능한 W셀만 치환한다. 원본 전체 상품/시트/서식/나머지 셀을 보존한다. 테스트 상품은 동일한 35컬럼의 테스트용 파일로 생성하며 실제 판매처 상품 식별값이 없음을 화면에 표시한다. 테스트 파일을 실상품 업로드용으로 주장하지 않는다.

실데이터 조회에서 1000-1~1000-9를 확인했고 1000-10은 조회되지 않았다. 테스트 조합 계산값은 0,1,3,확인필요다. UI에서 원본 엑셀의 Q2를 테스트값으로 바꿔 다운로드한 뒤 재검증한 결과, 셀 값은 Q2와 W2(1998→0)만 달랐고 모든 셀 스타일은 동일했다. 변경된 기존 ZIP 내용은 sheet1.xml 하나뿐이다. 이 검증용 수정 파일은 운영 업로드에 사용하지 않는다.

아래는 단계별 이전 구현 기록이며 가상 입력 방식은 위의 실재고 조회로 대체되었다.

사용자 요청에 따라 날짜별 주문 연동과 추가 재고 차감 개발을 취소했다. 주문수집은 기존 과정에서 처리하고, 이후 갱신한 개별 SKU 재고의 최솟값을 조합형 재고로 사용하는 방향으로 변경했다. 기존 조합형 재고는 계산에서 제외한다.

Q열 옵션관리코드를 개별 셀피아 SKU 연결 메모로 사용한다. SKU1/SKU2 또는 [SKU1],[SKU2] 형식을 지원하며 R열 조합 SKU는 그대로 둔다. Q열이 비어 있으면 미등록으로 표시한다. 현재 샘플은 옵션기본 35컬럼/90행이며 Q열은 모두 비어 있다.

이번 변경 범위는 전용 탭, 계산 기준/35컬럼 안내, 브라우저 내 Q열 연결값 파일 미리보기다. 개별 SKU 재고 조회와 계산값 저장/출력은 아직 구현하지 않았다. 사용자 파일의 상품/계정/연결 데이터는 정적 배포에 포함하지 않는다.

이전 주문 연동의 공개 및 private 진입 함수 권한을 취소하는 마이그레이션을 적용한다. 기존 테이블/이력은 삭제하지 않는다. 이전 화면과 데이터 서비스의 주문 연동 진입점도 제거했다. 피킹 코드와 스크래퍼는 수정하지 않았다.

검증: 관련 mock 테스트 79개 통과. 브라우저에서 실제 첨부 파일을 읽어 조합형 90행 / 연결값 0 / 미등록 90 / 형식 오류 0을 확인했다. DB의 이전 주문 연동 공개 함수 4개의 anon/authenticated 실행권한은 모두 false이며 작업/재고원장은 각각 0건이다.

취소 마이그레이션 파일 시각 20260908082306은 원격 이력 20260908082517(cancel_order_stock_integration)에 대응한다.

## 가상 상품과 상품별 하위 화면

추가 요청에 따라 첫 화면은 D열 온라인 상품명을 제목으로 한 상품 목록으로 변경했다. 상품을 선택하면 해당 상품의 조합 옵션만 하위 화면에 표시하며 목록으로 돌아갈 수 있다. 제목이 같아도 계정/판매자관리코드가 다른 상품은 합치지 않는다. 200개를 넘으면 더 보기로 이어서 확인한다.

가상 테스트 상품 1000에는 개별 SKU 1000-1부터 1000-10까지와 조합 4개를 준비했다. 초기 계산값은 1000-1+2=12, 1000-3+4+5=8, 1000-6+7+8=0, 1000-9+10=7이다. Q열 연결과 개별 재고, 기존 가상 조합 재고를 편집할 수 있다. 가상 재고 갱신은 최솟값을 가상 W값으로 반영한다. 기존 조합 재고 초기값 999는 계산에 사용하지 않는다.

가상 상태는 별도 localStorage 키 operations-hub-ably-virtual-lab-v1에만 저장하며 운영 DB나 외부 판매처에 쓰지 않는다. 테스트 초기화로 복구한다. 재고 누락, 음수/소수, 연결 형식 오류는 해당 조합을 제외하며 실제 0은 유효하다.

브라우저에서 첨부 파일의 상품 1개 → 하위 옵션 90행 탐색과 1000-2 재고 변경(12→5) → 조합 1000-1+2 가상 재고 갱신(999→5), 품절 조합 0 반영을 확인했다.
