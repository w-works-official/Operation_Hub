# SKU 종속관계 가격 내보내기

판매처 내보내기 카드의 `개별상품 → 모음전 가격 종속관계 적용`은 기본 OFF다. ON이면 일반 SKU 상위→하위 관계를 조회해 선택한 상위의 모든 하위를 가격 출력 범위에 추가한다. 하위만 선택했다면 필요한 상위는 입력으로만 읽는다.

상속하는 값은 상위의 **최종가 숫자**다. 하위 수식이나 하위의 기존 가격 결정을 다시 적용하지 않는다. 상위의 상품 등록가·할인·옵션가 tuple이나 가격 결정 identity를 하위에 복사하지 않는다. 모음전의 전체 옵션 최종가를 보존하면서 판매처 공통 등록가·할인·옵션가를 따로 구성한다. 스마트스토어는 가능한 경우 기존 공통가격을 유지하고, 불가능하면 중간 목표가 또는 기존 최저가 역산 경로를 검증한다. 표현할 수 없는 상품은 제외 사유를 표시하고 원본을 유지한다.

기존 `수식 적용 / 셀피아 판매가 기준`, 대상 SKU, 파일 출력 범위, 가격·재고 선택은 유지된다. 수식 모드의 상위에 판매처 수식이나 수정안이 없으면 현재 내부 Matrix 기준가격을 계산한다. 이 상위가 출력 대상에도 있다면 같은 가격을 명시적인 이번 출력 지시로 사용해 상위·하위 모두 일치시킨다. 원본 모드는 기존 현재 확정 가격 우선순위와 원본 판매가 경로를 따른다.

자동 포함된 하위에는 가격만 추가한다. 원래 선택 범위의 재고만 기존 방식으로 처리한다. 재고만 모드에서는 가격 종속 체크가 해제되고 비활성화된다. 별도 고급 선택 파일 변환은 이 옵션을 무시하지 않고 일반 내보내기를 이용하도록 안내한다.

현재 관계와 가격은 내보내기 요청마다 새로 읽으며 UI의 최대 1,000노드 캐시를 사용하지 않는다. `hub_export_sku_dependencies_read_v1`은 운영 세션을 검증하는 읽기 전용 RPC다. 최신 원본에 없는 SKU, 관련 비 SKU 노드, 자기 참조, 복수 상위, 순환과 범위 초과는 차단한다. 상위의 여러 판매처 연결 최종가가 다르면 임의 선택하지 않는다. 미리보기 후 관계·가격·결정 revision이 바뀌거나 요청이 취소되면 다운로드하지 않는다.

종속 옵션 ON 경로는 세 판매처 모두 `hub_price_decision_export_read_v3`으로 상품의 전체 형제 옵션과 가격 증거를 조회한다. 기존 에디터의 200 SKU 상품 한도를 큰 모음전에 재사용하지 않는다. 요청 입력은 200 SKU씩 나누되 각 상품은 최대 5,000 SKU, 한 요청의 확장은 최대 20,000 membership이며 초과 시 일부를 잘라 내보내지 않고 중단한다. 기존 `sellpia-export-v2` 증거 계약과 현재 확정 가격·매핑·원본 검증을 유지하며, OFF 경로와 기존 에디터·v1·v2 함수는 변경하지 않는다.

관계, 수식 배정, Matrix 가격, 현재 가격 결정, 연결·해제·숨김, 원본 DB 값을 저장하지 않는다. 에이블리의 명시된 대표가 정책과 기존 다운로드 차단도 유지한다.

## 검증과 롤백

- 순수 그래프/상속, 실제 가격 resolver·Rule Registry 서비스, PGlite 실제 마이그레이션과 권한/롤백 테스트를 실행한다.
- 실제 app·파서·XLSX 직렬화 통합 테스트에서 자동 하위 포함, 원래 형제 가격 보존, 최종가 상속, 다른 모음전 기본가와 음수/양수 옵션가, 변경된 미리보기·취소 차단을 확인한다.
- 브라우저 테스트에서 ON/OFF, 재고 전용, 미리보기 무효화, 부모 출처 표시 및 에이블리 실제 projection을 확인한다.
- 프런트엔드는 이전 Pages commit으로 복원할 수 있다. DB 역변경은 세션 gate → 큰 그룹 v3 → SKU 관계 v1 순서로 `supabase/rollback/`의 대응 SQL을 적용해 추가된 읽기 함수만 제거한다. 원본·운영 데이터 복원 작업은 필요하지 않다.
