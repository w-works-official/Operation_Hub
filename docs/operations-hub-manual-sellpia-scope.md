# 셀피아 상품번호와 SKU로 내보내기 대상 선택

판매처 내보내기의 `SKU 직접 입력`은 스마트스토어·메이크샵·에이블리 모두 셀피아 코드로 해석한다. `8008` 같은 상품번호는 해당 상품의 `8008-*` 옵션 SKU 전체로, `8008-3` 같은 완전한 SKU는 해당 SKU 하나로 해석한다. 정확한 SKU가 실제로 존재하면 기존 조회 기능의 정확 일치 우선 규칙을 유지한다. 상품번호와 옵션 SKU를 섞거나 반복 입력해도 최종 대상 SKU는 중복 제거한다. 앞자리 0을 포함한 코드는 문자열 그대로 유지한다.

기존 `SystemV3Data.resolveCodeEntries`와 `resolve_operations_hub_code_entries`의 `source:'sellpia'` 조회를 재사용한다. `manual-sku-scope.js`가 입력·응답 identity, 조회 상태, 정확 일치와 하이픈 경계, 누락된 입력, 모순된 응답을 검증한다. `8008`로 `80080-*`를 선택하지 않으며 완전한 옵션 SKU를 다시 접두어로 확장하지 않는다. DB 테이블·스키마·원본·판매처 연결·해제·숨김 설정은 변경하지 않는다.

## 조회와 화면 표시

입력 중에는 RPC를 호출하지 않는다. 미리보기·파일 생성·기존 명시적 재계산이 대상 범위를 요청할 때만 조회한다. 입력 전에는 `입력 N개 · 조회 전`, 조회 후에는 `입력 N개 → 셀피아 M SKU · 미발견 X개`를 표시한다. `입력별 조회 결과`를 펼치면 상품번호별 확장 수와 미발견 코드를 확인한다. 이는 셀피아에서 해석한 대상 수이며, 기존 판매처 연결 수·미연결 수·파일 행 수와 구분한다.

일부 미발견은 별도로 표시하고 발견한 SKU에 기존 부분 내보내기 정책을 적용한다. 모두 미발견이면 결과를 표시한 뒤 미리보기를 중단하고 파일을 생성하지 않는다. RPC 오류·응답 누락·불일치는 미발견으로 삼키지 않고 조회 오류로 중단한다. 입력이나 범위 모드를 바꾼 뒤 늦게 도착한 응답은 요약과 미리보기에 게시하지 않는다.

DB 조회는 입력 500개씩 나누되 각 요청의 확장 응답은 1,000행 단위로 끝까지 읽는다. exact count와 누적 행 수·응답 identity를 검증하여 서버 반환 제한으로 일부 옵션만 선택되는 것을 막는다. 코드 목록 업로드에서 사용하던 입력 순서와 중복 행도 유지한다.

## 미리보기와 생성 일치

`scopeSkus`의 `Set/null` 반환 계약을 유지하고 해석 보고서는 판매처별로 별도 관리한다. `전체 매칭 SKU`와 태그 선택은 기존 계약을 유지한다. 수식 적용·셀피아 원본가격, 가격·재고 필드, 상품별 판매가·할인, 모음전 종속관계는 해석된 실제 SKU를 받은 다음 기존 계산 순서로 처리한다. 입력 조회 자체가 가격을 재계산하거나 저장하지 않는다.

스마트스토어·메이크샵은 미리보기와 생성에서 확장 SKU 집합과 정규화된 입력 해석 결과를 비교한다. 에이블리도 동일한 집합과 해석 근거를 버전 토큰에 포함한다. 미리보기 후 옵션이 추가·제거되거나 해석이 바뀌면 파일을 만들지 않고 다시 미리보기를 요구한다. 원본 재업로드·운영 인증 만료 시 해석 보고서와 해당 미리보기를 무효화한다. 기존 가격·재고·원본 파일 검증도 계속 적용한다.

## 검증과 배포

순수 입력 해석, 실제 데이터 서비스의 1,000행 초과 응답, 실제 app·파서·XLSX 생성, 세 판매처 브라우저 흐름을 검증한다. `8008/8434/9992/10057`은 확인 시점의 셀피아 DB에서 각각 12/3/10/3개, 합계 28 SKU이다. 이 수는 실제 판매처 출력 행 수와 같다는 보장이 아니다. 실제 연결과 안전검사를 통과한 행만 기존 정책대로 내보낸다.

회귀·브라우저·정적 검사와 빌드 후 CI/Pages 완료와 운영 자산을 확인한다. 롤백은 프런트엔드 변경을 되돌리는 것으로 가능하며 DB 마이그레이션이나 데이터 복원이 필요하지 않다.
