# 접수일별 주문과 수동 재고 반영

> 2026-09-08 사용자 요청으로 이 개발 방향을 취소했다. 화면/데이터 서비스 연결을 제거하고 RPC 실행권한도 취소했다. 현재 방향은 ably-combinations-20260908.md를 참고한다. 아래는 취소 이전 구현 기록이다.

재고조사 탭에서 접수일(receipt_date)별 주문항목을 200건 단위로 조회한다. SKU 검색은 현재 페이지에 적용된다. 선택한 주문은 SKU별 재고 변경량을 미리 보고 적용할 수 있다.

- 미반영 수량 차감: 주문항목별 기존 반영량과의 차이만 차감한다.
- 이미 원본에 포함: 현재재고를 변경하지 않고 반영 사실만 기록한다.
- 재고 부족, 원본 변경, 재고 버전 충돌 등은 사유와 함께 제외한다.
- 요청 UUID로 재시도를 중복 처리하지 않는다. 최근 30개 본인 작업 이력을 다시 조회할 수 있다.
- 되돌리기는 이후 재고/원장 변경이 없을 때 재고와 반영 원장을 함께 복구한다.

피킹 DB는 고정 대상 HTTP GET으로 필요한 상품/주문항목 필드만 읽는다. 고객 이름, 주소, 전화번호를 수집하지 않는다. 피킹 코드, 스크래퍼, 피킹 DB에 대한 변경은 없다. 지원 상태는 재고매칭/상품매칭/송장입력이며 다른 상태는 확인 필요로 제외한다. 원본에서 사라진 주문을 취소로 추정하거나 자동 복원하지 않는다.

Operations Hub의 기존 운영자 세션 검증과 재고 저장 함수를 사용한다. 새 private 테이블은 RLS와 직접 접근 거부 정책을 적용하고 공개 RPC에서 세션을 검증한다. SKU 잠금 순서를 통일하고 저장 직전 원본/재고/원장 버전을 검증한다.

## 검증

- PostgreSQL(PGlite) 실제 SQL 시나리오 10개 통과: 권한, SKU 합산/부족, 중복 재시도, 원본 포함, 변경 충돌, 삭제된 원본, 지원 상태, 되돌리기, 이력, 잘못된 요청.
- 기존 Operations Hub mock 테스트 78개 통과. 오래된 캐시 버전 고정값과 변경된 메뉴명 기대값을 갱신하고 Windows 줄바꿈을 정규화했다.
- 로컬 브라우저에서 조회, 선택, 부족 제외, 20→15 반영, 새로고침 후 유지, 되돌리기 15→20, 접수일 변경을 확인했다.
- 운영 원본 읽기에서 2026-09-08 주문항목 383건(200+183), 선택 항목 45건 재조회 확인.
- 운영 검증에서는 실제 재고 반영을 실행하지 않았다. 새 작업/원장 테이블은 0건으로 확인했다.
- 새 private 테이블에 대한 보안 advisor 경고 없음.

이 변경은 7ee624f 기준의 별도 작업 디렉터리에서 작성했다. 이전 작업 디렉터리의 판매처 작업대 등 미커밋 변경은 포함하지 않았다.
