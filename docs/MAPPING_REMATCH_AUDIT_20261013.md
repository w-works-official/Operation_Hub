# 매칭 변경과 다중 연결: 2026-10-13 운영 읽기 전용 조사

이 문서는 Supabase 프로젝트 `bpgvqmtsjgegnrdzmpep`의 2026-10-13 16:31 KST 기준 관계 집계와 후속 제한 조회 결과를 기록한다. 운영 데이터, 연결, 원본 파일은 수정하지 않았다. 아래 수치는 당시 DB 상태이며, 이후 원본 업로드나 매칭 수정 시 달라질 수 있다.

`이 SKU의 연결 변경`은 이 브랜치에 구현된 UI 진입점이다. 이 문서는 해당 UI의 Production 배포 완료를 주장하지 않는다. 재고 완료 SQL 타임아웃 수정과 상품·옵션 재매칭은 별도 작업이다. 타임아웃 수정이 기존 옵션코드를 새 옵션코드로 자동 교체하지 않는다.

## 1. 관계를 구분하는 기준

판매처 identity는 **판매처 + 상품코드 + 옵션코드**이다. 상품코드가 같아도 옵션코드가 다르면 서로 다른 identity다.

| 화면 표시 / 현상 | 정확한 의미 |
|---|---|
| `1:N` | 같은 판매처에서 셀피아 SKU 하나가 여러 상품·옵션 identity에 연결됨 |
| `조합 2SKU` 등 | 판매처 상품·옵션 identity 하나에 여러 셀피아 SKU가 연결됨 |
| `1:N+조합` | 위 두 조건이 함께 존재 |
| 동일 상품코드의 여러 옵션 행 | 셀피아 SKU별로 판매처 옵션이 하나씩 연결되는 일반적인 상품 구조일 수 있음 |
| 상품코드·상품명 셀 병합 | 같은 셀피아 상품 그룹, 판매처 상품코드, 상품명, 초안 상태를 가진 연속 행의 UI 병합 |

`조합` 배지는 연결 수로 판정한다. 실제로 여러 부품을 함께 판매하는 세트인지, 과거 수동 매칭이 중복된 것인지는 상품과 옵션 의미를 확인해야 한다. 배지 자체는 물리적인 세트 판매의 증거가 아니다.

## 6. 새 UI 진입점과 재매칭 범위

매트릭스 판매처 셀의 메뉴 및 연결 관리 팝업에 `이 SKU의 연결 변경` 진입점이 추가되어 있다. 현재 SKU의 최신 상품과 전체 연결을 다시 읽은 뒤 경로를 결정한다.

| 현재 연결 상태 | `이 SKU의 연결 변경` 경로 |
|---|---|
| 일반 manual/legacy 단일 판매 대상 | 최신 원본 상품·옵션 검색에서 기존 연결 교체. 사전 연결 해제 불필요 |
| legacy 옵션 공유만 존재하는 11017 같은 사례 | 현재 SKU의 단일 판매 대상 변경으로 처리. 같은 구 옵션의 다른 SKU 연결은 별도 행에서 변경 |
| 여러 판매 대상 또는 활성 explicit 구성 | 기존 다중·조합 관리로 이동해 필요한 구성/대상만 수정 |
| 에이블리 verified solution-code 연결 | 기존 에이블리 솔루션사 코드 매핑 관리로 이동 |

일반 `link_operations_hub_seller_item_v2`는 동일 SKU·판매처 manual 연결을 upsert로 교체하고 그 SKU·판매처의 legacy cache를 지운 뒤 새 연결만 삽입한다. 다른 identity의 explicit component를 모두 비활성화하지 않으며, 에이블리 verified ledger도 제거하지 않는다. 기존 여러 판매 대상이 정당한 경우 모두 해제하는 방식으로 처리하면 안 된다.

에이블리 일반 일괄 업로드만으로 verified identity의 교체가 완료됐다고 판단할 수 없다. 같은 identity에서는 canonical verified SKU가 legacy보다 우선하며, 서로 다른 identity에서는 양쪽이 남을 수 있다. 별도 매핑 관리에서 해당 레코드의 SKU·상태와 실제 판매 대상 여부를 확인해야 한다.

에이블리 `내보내기 대상 사용` OFF는 공식 재고 내보내기에서 제외하는 설정이다. 당시 `ably_mapping_verified_read_v1`은 `mapping_state='verified' AND sellpia_sku_code IS NOT NULL`을 사용하며 `is_active`를 보지 않는다. **OFF만으로 매트릭스 canonical 연결이 지워지지 않는다.** 상태·억제·원본·SKU를 함께 검토해야 한다.

## 7. 재고와 내보내기에서 확인한 동작

- 다중·조합 관리 graph의 계산재고는 `min(floor(각 SKU 가용재고 / 구성수량))`이다. 구성 재고를 합산하지 않는다. 가용재고를 모두 확인할 수 없으면 NULL이다.
- graph에서 계산된 재고를 현재 스스·메이크샵 재고 내보내기에 자동 적용한다고 주장할 수 없다. 현재 carrier 경로는 exact 상품·옵션 identity의 소유 SKU가 한 개여야 수량을 쓴다.
- 복수 소유 SKU이면 `판매처 상품·옵션이 여러 SKU에 연결되어 있어 자동으로 쓸 수 없습니다.`로 차단하고 원본을 유지한다. 미연결 identity는 원본 유지 경고다.
- 재고 반영 후 4파일 생성 batch도 스스·메이크샵을 `includePrice:false`, `includeStock:true`로 같은 carrier 검사 경로에 전달한다. 조합 배지만 보고 수량이 합산되거나 최솟값으로 내보내진다고 추정하면 안 된다.
- 에이블리 공식 재고 파일은 별도 verified ledger를 사용한다. shared 정책은 연결된 단일 셀피아 SKU의 선택 재고를 읽고, individual 정책은 저장된 개별 수량을 쓴다. 당시 verified active 6,840건은 모두 shared, 나머지 474건은 review inactive다.
- 11017의 새 옵션 12개에는 구 identity가 exact 매칭되지 않는다. 새 매칭을 확정해야 새 옵션의 재고 target이 결정된다. SQL 타임아웃 수정 배포와는 별도의 운영 매칭 작업이다.
