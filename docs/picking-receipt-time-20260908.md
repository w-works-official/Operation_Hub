# 피킹 접수 시각 보관 — 2026-09-08

> **철회됨:** 사용자는 스크래퍼 변경과 접수 시각 보관을 원하지 않음을 명확히 했다. 스크래퍼와 어댑터를 원복한다. 아래 내용은 철회한 작업의 이력이지 현재 사용 안내가 아니다. 추가 DB 컬럼은 삭제하지 않고 미사용으로 남긴다. 개발 대상은 상품운영 프론트이며 피킹/스크래퍼는 기존 데이터 조회 출처로만 사용한다.

## 적용 범위

- 피킹 프로젝트 `vgxocngpykhlkosiaeew`의 order_items 및 stg_order_items에 접수 시각, 정밀도, 원문 컬럼을 추가했다. 기존 행은 null 유지. 주문 수량, 재고, 접수일, 권한 변경 없음.
- 셀피아 전체상품리스트는 재고 기준 원본이다. 주문 파일을 별도로 요구하지 않고 기존 피킹 스크랩의 접수정보를 사용한다.
- 새 북마크는 주문상품마다 원본 접수정보를 보관한다. 기존 접수기간 조회/오전·오후 구분/최초 접수일 보존은 유지한다.
- 초/분 단위 정밀도를 구별하며, 날짜만 있거나 해석이 불가능한 경우 정확한 시각을 만들지 않는다. 피킹 스크랩 실행 시간을 접수 시각으로 사용하지 않는다.
- 접수 시각은 원본 출처 정보이며 셀피아의 실제 재고 차감 완료 시각을 증명하지는 않는다. 재고 동기화에서 사용할 때 이 전제 및 분 단위 경계 처리를 유지해야 한다.

## 사용 방법

`tools/sellpia_scraper.html`의 **0908-접수시각 보관** 버튼을 북마크바에 새로 등록한다. 기존 북마크의 내장 코드는 자동으로 바뀌지 않는다.
재스크랩한 주문상품부터 접수 시각이 채워진다. 전체 스크랩은 기존 주문/상품 교체 기능을 포함하므로 피킹 작업 중에는 실행하지 않는다. 개발 검증을 위해 실제 재스크랩은 실행하지 않았다.

## 검증 및 남은 작업

- 합성 데이터: KST/UTC, 오전/오후 12시, 초/분/날짜만 있는 값, 잘못된 날짜/시간, 어댑터 전달, 최종 북마크 구문 및 주문상품 저장 연결 검증 통과.
- 기존 스크랩 회귀 테스트 3개 통과: 최초 접수일 보존, 주문메모 출처, 전체 수집 확인 및 안내.
- 로컬 PGlite: 마이그레이션 2회 적용, 기존 수량 유지/시각 null, KST timestamp 저장·조회 검증 통과.
- 원격 DB: 6개 컬럼 확인, 접수 시각을 가진 기존 행 0건, 대기 잠금 0건. 테스트 주문 생성/삭제 없음.
- 아직 미완료: 실제 새 북마크 재스크랩으로 원본 시간 형식 확인, 재고 기준 채택 및 원장 원자 저장, 오늘 주문 동기화 버튼/미리보기/실행취소, 입고라벨 재고 가산.
- 이번 배포는 접수 시각 보관의 선행 단계이며, 재고 차감 버튼 완성으로 보고하지 않는다. Operations Hub의 미배포 작업 묶음은 포함하지 않는다.
