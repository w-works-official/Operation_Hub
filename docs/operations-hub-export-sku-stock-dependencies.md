# 재고조사 후 SKU 종속관계 재고 내보내기

재고관리 탭의 `개별상품 → 모음전 재고 종속관계 적용`은 기본 OFF다. 가격 내보내기의 종속 옵션과 독립적인 설정이며, 선택한 `재고 / 가용재고` 기준을 그대로 사용한다. ON이면 일반 SKU 그래프의 최초 상위 수량을 하위·후손의 파일 재고로 복사한다. 상위 3 → 하위 3 → 후손 3이며 구성수량을 곱하거나 나누지 않는다.

## 처리 순서

1. 판매처 최신 원본과 매핑을 읽고 관계 구조를 검사한다. 구조 오류는 재고조사 업로드 전에 중단한다.
2. 기존 재고조사 비교·업로드 계약대로 실제 입력 변경 SKU만 DB에 반영한다. 자식 조사 행을 합성하거나 자식 DB 재고를 덮어쓰지 않는다.
3. 새 snapshot의 Matrix 재구성이 끝나면 그 snapshot의 관계를 새로 고정한다. 업로드 전 그래프 version에는 이전 snapshot이 들어 있으므로 업로드 후 검증에 재사용하지 않는다.
4. 판매처 미매핑 상위와 필요한 후손까지 원시 재고를 조회한다. 원시 Map은 보존하고 파일 생성용 Map만 복사하여 선택 필드를 상속한다. 판매처에 없는 행을 새로 만들지는 않는다.
5. 스마트스토어 2개·메이크샵 1개·에이블리 1개 XLSX를 생성하고 다시 연다. 가격·상품명·코드·행·양식은 보존한다.
6. 결과 파일을 반환하기 전에 원시 재고, 관계 version, 스마트스토어·메이크샵 SKU 연결과 최신 원본, 에이블리 매핑을 다시 확인한다. 변경되면 파일을 반환하지 않는다.

0은 유효한 수량이다. 원본 물리 재고의 음수는 기존 정책을 유지하며, 음수 가용재고는 원본 값을 보존하고 판매처 파일에서만 기존 정책대로 0으로 처리한다. 차단·누락·유효하지 않은 상위나 중간 SKU가 있으면 후손도 차단하고, 자식의 옛 수량으로 대체하지 않는다. 차단 사유는 기존 차단 목록에 포함한다.

## 에이블리와 별도 조합 기능

에이블리 공식 재고 파일은 활성·검증된 `shared` 및 이전 `individual` 매핑 모두 다른 판매처와 같은 셀피아 재고 기준을 사용한다. 과거 `individual_stock`은 더 이상 출력 수량으로 사용하지 않는다. 매핑 화면에서 새 개별 수량 입력을 제거했다. 이전 설정을 열거나 취소해도 DB는 바뀌지 않으며, SKU·상태만 수정 저장할 때도 이전 정책·개별 수량 메타데이터는 그대로 보존한다. 신규 매핑은 `shared`로 저장한다. 사용자가 검토·제외 정책을 명시 선택하면 기존 DB 제약대로 현재 개별 수량은 null로 전환하고 이전 값은 감사 이력에 보존한다.

에이블리 1+1 조합 탭의 구성 SKU별 최솟값 계산과 별도 BOM 수량 계산은 변경하지 않는다. 판매처 옵션의 다중 SKU 연결 차단, 검토·제외·숨김·연결 억제도 유지한다.

## 재시도와 검증

생성 실패 후 업로드 성공 snapshot은 보존한다. 재시도는 기본적으로 저장된 종속 선택을 사용하고, 명시적으로 선택을 바꿔도 재업로드 없이 파일만 다시 생성한다. 화면에서는 설정 변경 시 이전 파일 링크와 재시도 계약을 무효화하며, 비교·생성·저장 위치 선택 중에는 컨트롤을 잠근다.

실제 app 함수·파서·XLSX 변환기 통합 테스트로 ON/OFF, 여러 단계 상속, 판매처 미매핑 상위, 물리/가용 수량, 자식 DB 불변, 생성 중 변경 차단, 재업로드 없는 재시도와 네 파일의 비재고 셀 보존을 확인한다. 원시 Map 불변과 차단 전파는 별도 순수 helper 테스트로 검증한다.
